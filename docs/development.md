# Разработка и отладка

## Рабочий цикл

Сборки нет — исходники грузятся как есть.

1. `chrome://extensions` → **Загрузить распакованное** → папка с `manifest.json`.
2. После правки нажать **Обновить** на карточке расширения.
3. Правки в `content/overlay.js` требуют ещё и перезагрузки открытых вкладок сайта:
   старый content script остаётся в них жить.
4. Правки в `stats/`, `options/`, `popup/` подхватываются простым обновлением страницы.

Изменения стилей плашки и списка сайтов применяются к открытым вкладкам **без** перезагрузки —
это работает через подписку на `storage.onChanged`, ломать её не стоит.

## Где смотреть логи

| Что | Где |
|---|---|
| service worker | `chrome://extensions` → карточка → ссылка **service worker** |
| content script | обычный DevTools вкладки сайта |
| страницы расширения | DevTools соответствующей вкладки |

Полезные команды в консоли service worker:

```js
await chrome.storage.local.get(null)     // весь стейт
await chrome.storage.session.get('tracker')  // что тикает прямо сейчас
await chrome.alarms.getAll()             // жив ли периодический flush
chrome.idle.queryState(60, console.log)  // как Chrome видит активность пользователя
```

## Что легко сломать

- **Двойной учёт.** Писать в `daily`/`totals` откуда-либо кроме `flush()` в service worker нельзя.
  Content script и попап только читают.
- **Гонки.** Мутации состояния идут через `serialize()`, записи в storage — через `serializeWrite()`.
  Обработчик, меняющий состояние, оборачивает всё в один `serialize()` и зовёт внутри
  `doRecompute()`; вызов `recompute()` изнутри очереди — дедлок.
- **Кеш окружения.** Фокус окна и idle нельзя запоминать между вызовами: событие может пройти,
  пока воркер выгружен, и трекер замрёт навсегда. Спрашивай `queryState`/`windows.get` каждый раз.
- **Пересоздание alarm.** `alarms.create` с тем же именем сбрасывает таймер — сначала `alarms.get`.
- **Выгрузка воркера.** MV3 усыпляет его примерно через 30 секунд. Любое состояние, которое
  должно пережить сон, обязано попасть в `chrome.storage.session` через `persist()`.
- **`import` в content script.** Не поддерживается — `overlay.js` самодостаточен.
- **Внешние ресурсы.** CSP MV3 блокирует CDN, шрифты и удалённые скрипты. Графики рисуются
  вручную в `src/stats/charts.js`.
- **`hidden` + `display: flex`.** В `src/common/ui.css` есть правило `[hidden] { display: none !important }` —
  без него атрибут `hidden` не скрывает flex- и grid-контейнеры.
- **Протечка стилей сайта.** Плашка живёт в закрытом Shadow DOM; выносить её разметку наружу нельзя.
- **Забытый перевод.** Любая новая строка добавляется сразу во все четыре `_locales/*/messages.json`
  (`en` — fallback, поэтому в нём ключ обязан быть). Ключ без перевода отрисуется самим ключом:
  `t()` возвращает его, когда `chrome.i18n.getMessage` отдал пустую строку.

## Локализация

Тексты лежат в `_locales/<lang>/messages.json`, язык выбирает Chrome по языку интерфейса
браузера, `default_locale` в манифесте — `en`.

- **HTML**: атрибут `data-i18n="ключ"` (текст), `data-i18n-html` (сообщения с `<b>`),
  `data-i18n-title`, `data-i18n-placeholder`; страница зовёт `applyI18n()` на старте.
- **JS страниц расширения**: `t('ключ', [подстановки])` из `src/common/i18n.js`.
- **Content script**: `import` не работает, поэтому в `overlay.js` свой однострочный `t()`
  поверх `chrome.i18n.getMessage` — он доступен в content script без дополнительных permissions.
- **Даты**: названия месяцев и дней недели не переводим вручную — их даёт `Intl.DateTimeFormat`
  с локалью `uiLocale()` (`formatDayLabel` в `time.js`, подписи календаря в `charts.js`).
- **Проверка**: чтобы увидеть другой язык, запусти Chrome с `--lang=de` (или смени язык
  интерфейса в настройках браузера) и перезагрузи расширение.

Согласованность ключей между локалями стоит проверять после правок — наборы ключей во всех
четырёх файлах обязаны совпадать.

## Ручная проверка

Сквозной сценарий, покрывающий основное:

1. Добавить `youtube.com` как «трату времени» и `github.com` как «статистику».
2. Открыть YouTube — полноэкранная красная плашка, через 5 сек сворачивается в бейдж,
   счётчик сессии тикает раз в секунду.
3. Переключиться на другую вкладку на 10 сек, вернуться — сессия продолжилась, «сегодня» выросло
   ровно на время присутствия.
4. Закрыть вкладку, открыть заново — сессия с нуля, «сегодня» сохранилось.
5. Свернуть окно на минуту — «сегодня» не растёт.
6. Открыть GitHub — маленькая полупрозрачная плашка в углу, страница читаема.
7. Клик по плашке — открывается статистика по этому сайту, графики отрисованы.
8. Поменять цвет и расположение в настройках — открытая вкладка перекрашивается сразу.
9. Крестик на плашке GitHub — плашка исчезла, время продолжает расти; на YouTube крестика нет.
   Выключить «Плашку „Статистика“ можно закрыть» — плашка GitHub возвращается сразу.
10. Сбросить «за сегодня» — счётчик дня обнулился, «всего» уменьшилось на ту же величину.
11. Консоль service worker — без ошибок; после минуты простоя воркер выгружается, время
    не теряется (работает alarm-flush).

## Автоматическая проверка

Чистые функции (`match.js`, `time.js`, агрегации `storage.js`) не зависят от `chrome.*`
и проверяются обычным Node: скопировать `src/common/*.js` во временную папку с
`package.json` вида `{"type":"module"}` и прогнать `node --test` или простой скрипт с `assert`.
Покрывать стоит `normalizeDomain`, `matchSite` (в том числе приоритет более конкретного домена
и `enabled: false`), ключи дат и агрегации.

Расширение целиком гоняется в Chromium через Playwright:

```js
chromium.launchPersistentContext(profileDir, {
  headless: false,
  args: [`--disable-extensions-except=${EXT}`, `--load-extension=${EXT}`],
});
const sw = ctx.serviceWorkers()[0] ?? await ctx.waitForEvent('serviceworker');
const extId = new URL(sw.url()).host;   // chrome-extension://<extId>/src/options/options.html
```

Три грабли, на которые стоит заложиться заранее:

- **Гонка на старте.** Расширение само инициализирует хранилище при установке. Если записать
  своё состояние сразу после запуска, оно затрётся — надо дождаться появления `settings` и `sites`
  в `chrome.storage.local`.
- **Системный idle.** Синтетические события Playwright реальную мышь не двигают, поэтому Chrome
  быстро считает систему бездействующей и счётчик честно встаёт. В тестах помогает
  `idleTimeoutSec: 3600`.
- **Фокус окна.** Без реального фокуса окна ОС трекер честно стоит на паузе и тест ничего
  не измерит. `chrome.windows.update(id, { focused: true })` помогает не всегда; надёжнее
  вызвать `SetForegroundWindow` через PowerShell — **обязательно фильтруя процессы по PID
  тестового браузера**, иначе на передний план выйдет личное окно Chrome пользователя.

Время попадает в `chrome.storage.local` не мгновенно, а на переходах и раз в минуту —
чтобы увидеть накопленное сразу, надо спровоцировать flush (переключить вкладку) или
прочитать `chrome.storage.session.get('tracker')`.

## Идеи для доработки

- Лимиты времени с уведомлением или блокировкой сайта после порога.
- Учёт по путям внутри домена (`reddit.com/r/all` отдельно от остального).
- Синхронизация настроек через `chrome.storage.sync`.
- Ежедневный или еженедельный отчёт в попапе.
