# Архитектура

## Принцип

Время считает **только** service worker (`src/bg/service-worker.js`). Content script рисует плашку
и запрашивает готовые числа сообщениями; попап и страница статистики читают storage напрямую.
Так несколько вкладок одного сайта не удваивают учёт, а данные переживают перезагрузку страницы.

```
tabs/windows/idle/webNavigation events
            ↓
      service-worker.js  ──flush──►  chrome.storage.local (daily, totals)
            ↑    │                          ↑
   sendMessage   │ statsForTab()            │ getState()
            │    ▼                          │
      overlay.js (Shadow DOM)      stats.js / options.js / popup.js
```

## Состояние трекера

В памяти воркера (и зеркалом в `chrome.storage.session` под ключом `tracker`):

```js
{
  sessions: { [tabId]: { siteId, sec } },  // непрерывная сессия каждой вкладки
  active:   { tabId, siteId, startedAt },  // что тикает прямо сейчас (или null)
}
```

`chrome.storage.session` нужен потому, что MV3 выгружает воркер примерно через 30 секунд простоя.
При каждом пробуждении `load()` восстанавливает состояние, `chrome.runtime.onStartup` очищает его —
вкладок из прошлого запуска браузера уже не существует.

Фокус окна и активность пользователя **не кешируются**: `doRecompute()` каждый раз спрашивает
`chrome.idle.queryState` и `chrome.windows.get(...).focused`. Кеш здесь опасен — событие
`onFocusChanged` может произойти, пока воркер выгружен, и тогда запомненное «окно не в фокусе»
осталось бы навсегда: сайт молча перестал бы учитываться до следующего переключения окон.

### Сериализация

Все мутации состояния проходят через очередь `serialize()`, а записи в storage — через
`serializeWrite()` в `src/common/storage.js`. Обработчики событий асинхронные, и на сайтах
с активной навигацией их прилетает по нескольку разом: без очереди два параллельных
«прочитать — изменить — записать» читают одну копию `daily`, и записанное первым затирается —
статистика откатывается назад.

Обработчик, которому нужно изменить состояние перед пересчётом, оборачивает всё в один
`serialize()` и вызывает внутри `doRecompute()` напрямую. Вызывать `recompute()` внутри
очереди нельзя — это дедлок.

## Цикл учёта

`recompute()` — единственная точка принятия решения, вызывается на каждое событие:

1. Спрашивается текущий idle; если система бездействует — вкладка не берётся вовсе.
2. `getFocusedTab()` отдаёт активную вкладку окна, которое **сейчас** в фокусе, иначе `null`.
3. Нет вкладки или её сайт не отслеживается → `stopTracking()` (flush + `active = null`).
4. Контекст тот же — просто `flush()`.
5. Контекст сменился — `flush()` прежнего и `startTracking(tabId, siteId)`.

`flush(now)` записывает `(now - startedAt)` в `sessions[tabId].sec` и в storage через
`addSeconds(siteId, delta)`, после чего переставляет `startedAt = now`. Дельты меньше полусекунды
отбрасываются, а сверху ограничены `MAX_FLUSH_SEC` (5 минут): при рабочем alarm дельта не
превышает минуты, всё большее — сон машины, а не время на сайте.

`startTracking` обнуляет сессию только если вкладка новая или сменился сайт — переключение
между вкладками сессию сохраняет.

## Источники событий

| Событие | Зачем |
|---|---|
| `tabs.onActivated` | переключение вкладок |
| `tabs.onUpdated` (url/status) | навигация; уход с домена чистит сессию вкладки |
| `tabs.onRemoved` | закрытие вкладки — flush и удаление сессии |
| `windows.onFocusChanged` | уход из браузера / сворачивание окна (`WINDOW_ID_NONE`) |
| `idle.onStateChanged` | бездействие пользователя; интервал — `idle.setDetectionInterval` |
| `webNavigation.onHistoryStateUpdated` | SPA-навигация через `pushState` |
| `alarms` («flush», раз в минуту) | периодическая фиксация, чтобы усыпление воркера не съело время |
| `storage.onChanged` | правки настроек и списка сайтов применяются на лету |

Минимальный период `chrome.alarms` в MV3 — одна минута, поэтому максимально возможная потеря
при жёстком завершении браузера — около минуты активного времени.

⚠️ `chrome.alarms.create` с существующим именем **пересоздаёт** alarm и сбрасывает его таймер.
Воркер просыпается на каждое событие вкладок, поэтому безусловный `create` при старте означал бы,
что периодический flush не срабатывает никогда. `setupAlarm()` сначала проверяет `alarms.get`.

## Обмен сообщениями

`chrome.runtime.onMessage` в воркере, все ответы асинхронные (`return true` в листенере):

| Сообщение | Кто шлёт | Ответ |
|---|---|---|
| `{type:'hello', url}` | content script при инъекции | `{tracked:false}` либо `{tracked:true, site, style, settings, stats}` |
| `{type:'sync', siteId}` | content script раз в 15 сек | `{session, today, month, total, running}` — сессия **этой** вкладки |
| `{type:'stats', siteId}` | попап | то же, но сессия глобально активной вкладки |
| `{type:'openStats', siteId}` | клик по плашке | открывает `stats.html?site=<id>` |
| `{type:'openOptions'}` | — | открывает страницу настроек |
| `{type:'flushNow'}` | отладка | принудительная фиксация |

`statsFor()` добавляет к сохранённым числам ещё не записанные секунды текущего тика, поэтому
плашка и попап показывают время без «ступенек» на границах flush.

## Content script

`src/content/overlay.js` инжектится на `<all_urls>` при `document_start` и первым делом шлёт
`hello`. Если сайт не отслеживается — молча выходит.

- Плашка живёт в **закрытом Shadow DOM** (`mode: 'closed'`) на контейнере
  `#__site_time_tracker__` с `z-index: 2147483647`: стили сайта не протекают внутрь и наоборот.
- Между ресинками счётчик докручивается локально раз в секунду. Локальный тик останавливается
  при `visibilitychange`/`blur` и при собственном простое (`mousemove`, `keydown`, `wheel`,
  `scroll`, `touchstart`), чтобы не расходиться с воркером.
- `applyLayout()` переводит пресет стиля в геометрию: `fullscreen` → `inset: 0`;
  `edge` → растяжка по краю на `size` пикселей; `corner` и любой свёрнутый вид → скруглённый
  бейдж в углу на `collapsedSize`.
- Подписка на `storage.onChanged` применяет новые стили без перезагрузки, поднимает плашку,
  если сайт только что добавили, и снимает её (`teardown()`), если сайт удалили или выключили.
- Content script **не может** импортировать ES-модули, поэтому `overlay.js` самодостаточен —
  форматтеры времени в нём продублированы намеренно.

## Страницы расширения

`stats.js`, `options.js`, `popup.js` — ES-модули (`<script type="module">`), импортируют
`src/common/`. Все три подписаны на `storage.onChanged` и перерисовываются при изменениях,
поэтому настройки и статистика в разных вкладках не расходятся.

Графики (`src/stats/charts.js`) рисуются вручную через `createElementNS` — никаких библиотек,
подсказки реализованы `<title>` внутри SVG-элементов.

## Разрешения

| Permission | Зачем |
|---|---|
| `storage` | статистика и настройки |
| `tabs` | URL активной вкладки, открытие статистики |
| `idle` | пауза при бездействии |
| `alarms` | периодический flush |
| `webNavigation` | SPA-навигация |
| `host_permissions: <all_urls>` | плашка на любом сайте из списка |
